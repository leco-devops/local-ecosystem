Service hubs

Each hub is a single-service operations page for the local ecosystem: what the service does, how it fits the platform, live Docker status, credentials, connection strings, and every *.lh URL you can open from the browser.

Use hubs when you need passwords, JDBC/Redis URLs, MinIO keys, or CF-local adapter endpoints without digging through compose files. Status and metrics refresh with the dashboard toolbar.

UI access (local dev)

Store login credentials for MinIO console, Adminer, n8n, Open WebUI, and file-transfer (SFTP, FTP, read-only browser at files.lh). Auto-login opens a short-lived magic link (~60s) for web UIs with sign-in. Edit and Reset & apply update vault secrets and push them to running containers (including SFTP/FTP via file-transfer/.env). Requires the control token on the Control tab when DASHBOARD_CONTROL_TOKEN is set.

AI providers (LLM access)

Connect an external AI provider — Anthropic (Claude API), Google (Gemini API), OpenAI, Eden AI, or an aggregator such as OpenRouter, Groq, Together, Mistral or DeepSeek — plus self-hosted gateways (LiteLLM, vLLM, LM Studio) and the local Ollama / AirLLM services. On connect LEco DevOps discovers the provider's real model catalogue so you pick a model rather than typing one from memory. The chosen provider drives AI-assisted onboarding on the Hosted apps tab and other AI-assisted LEco tasks. Credentials are stored server-side only in config/ai-providers.yaml (gitignored, mode 0600) and are never returned to the browser in full. Saving requires the control token on the Control tab when DASHBOARD_CONTROL_TOKEN is set.
