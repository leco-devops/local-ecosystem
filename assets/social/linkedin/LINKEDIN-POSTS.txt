──────────────── OPTION A — the problem hook ────────────────

Every team has that laptop folder: an eleven-step README, four steps wrong, and a note that says "ask Priya about the ports."

We built LEco DevOps to delete that.

Point it at a repo. It reads your Compose, Wrangler, .env and Dockerfiles, writes the platform wiring beside your repo (never inside it), merges Traefik routes, deploys, and then proves it with a real HTTP probe. Your app answers on https://myapp.lh with TLS the browser trusts, in the same routing shape as production.

One rule we do not bend: ports come from evidence, never from invention. If the repo does not say which port a service listens on, we ask instead of guessing a plausible number and handing you a stack that builds, starts and serves nothing.

Free, MIT, community-governed. 65 MCP tools so an AI agent can drive the whole thing, through the same API as the UI, with no Docker socket of its own.

Full write-up in the article below, with the data flow, the runtime topology and the capability map.

#DevOps #OpenSource #Docker #Traefik #PlatformEngineering #MCP


──────────────── OPTION B — the "one control plane" hook ────────────────

Three ways into a LEco machine: a browser, an AI agent over MCP, and a git push.
Exactly one room behind them.

Neither the MCP server nor the CI/CD runner touches Docker. Both act through the dashboard API, so the control token, the lifecycle rules, the destructive-action gates and the audit log live in one place instead of three.

And every deploy ends in a real HTTP probe. A deploy that leaves the app returning 502 is recorded as failed, not as deployed, and classified as route_missing, backend_unreachable, tls_invalid or unhealthy, because those need four different fixes and a bare 502 names none of them.

That is LEco DevOps: an open-source local cloud edge for the apps you already have. Article below.
